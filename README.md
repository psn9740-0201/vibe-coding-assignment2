# 세상너무빨리변하는기술소식

IT 뉴스(AI·반도체·클라우드·사이버보안·통신·플랫폼)와 정부 정책(과기정통부·산업부·행안부) 소식을
보여주는 웹페이지입니다.

- **메인 배너 '오늘의 IT 업계 브리핑'**: 기준일 기사들을 종합한 3줄 브리핑 (핵심 이슈 / 산업 동향 / 정책·시사점)
- **IT 주요 뉴스** 최대 10건(분야별로 골고루), **정부 정책 변경** 최대 3건(부처별 1건)
- 각 기사는 **헤드라인(원문 링크) + 업계 영향** 형식이며, 헤드라인을 누르면 원문이 새 창으로 열립니다
- **기준일**을 골라 지난 날짜의 뉴스와 브리핑도 볼 수 있습니다
- 프레임워크 없이 **Node.js + HTML/CSS/JavaScript**로 만들었습니다
- 뉴스는 **API Key가 필요 없는 무료 RSS**에서 가져옵니다
- 배너의 AI 분석에만 OpenAI API Key가 필요하며, 키가 없어도 사이트는 정상 동작합니다 (아래 참고)
- 헤더는 오늘 날짜의 계절(12~2월 겨울 · 3~5월 봄 · 6~8월 여름 · 9~11월 가을)에 맞춰 빈티지 수채화풍 코기 그림과 움직이는 효과(눈 · 꽃잎 · 민들레 씨앗 · 낙엽)로 바뀝니다. 그림은 모두 직접 그린 SVG 코드이며 외부 API나 이미지 파일을 쓰지 않습니다

## 실행 방법

1. **Node.js 설치 확인** (18 이상 필요)
   터미널을 열고 다음을 입력합니다. `v18.x.x` 이상이 나오면 됩니다.
   ```bash
   node -v
   ```
   설치되어 있지 않다면 https://nodejs.org 에서 LTS 버전을 설치하세요.

2. **프로젝트 내려받기 및 폴더로 이동**
   ```bash
   git clone <이 저장소 주소>
   cd <저장소 폴더 이름>
   ```

3. **패키지 설치** (배너 AI 분석용 OpenAI SDK `openai` 하나만 설치됩니다)
   ```bash
   npm install
   ```
   설치하지 않아도 사이트는 동작하며, 이때 배너는 '자동 집계'로 표시됩니다.

4. **(선택) 배너 AI 분석 켜기 — `.env` 파일에 API 키 넣기**
   `.env.example`을 복사해 `.env`를 만들고(이미 있으면 생략), `OPENAI_API_KEY=` 뒤에 키를 붙여 넣습니다.
   ```bash
   cp .env.example .env
   ```
   ```ini
   OPENAI_API_KEY=sk-...본인 키...
   OPENAI_MODEL=gpt-4o-mini
   ```
   - 서버가 시작될 때 `.env`를 자동으로 읽습니다 (Node.js 내장 `process.loadEnvFile`, 별도 패키지 불필요).
   - 키를 바꿨다면 서버를 껐다가 다시 켜야 반영됩니다.
   - API 사용량만큼 요금이 부과됩니다 (같은 날짜의 배너는 30분 동안 캐시되어 다시 호출하지 않습니다).

5. **서버 실행**
   ```bash
   npm start
   ```
   또는 `node backend/server.js`
   `✅ 서버 실행 중: http://localhost:3000` 이 보이면 성공입니다.
   바로 아래 줄에 `배너 AI 분석: 켜짐 (모델 gpt-4o-mini)`이 보이면 `.env`의 키가 정상적으로 읽힌 것입니다.

6. **브라우저에서 열기**
   http://localhost:3000 에 접속합니다. 첫 로딩은 뉴스를 모으느라 몇 초 걸릴 수 있고,
   AI 분석을 켰다면 배너 작성에 수십 초가 더 걸릴 수 있습니다.

7. **사용하기**
   - **기준일**: 날짜를 바꾸면 그날의 뉴스·정책·배너를 다시 만듭니다 (오늘 이후는 선택 불가)
   - **새로고침** 버튼: 최신 뉴스를 새로 가져옵니다 (뉴스 캐시 무시)
   - **분야 탭**(AI/반도체/클라우드/사이버보안/통신/플랫폼): 해당 분야만 보기
   - 오늘 날짜를 보고 있으면 30분마다 자동으로 갱신됩니다

8. **종료**: 서버를 실행한 터미널에서 `Ctrl + C`

> 포트 3000이 이미 사용 중이면 `PORT=4000 npm start`로 실행하고 http://localhost:4000 에 접속하세요.
> `frontend/index.html`을 더블클릭해서 바로 열면 API를 호출할 수 없으므로, 반드시 서버를 통해 접속하세요.

## 별칭 DB (`data/aliases.json`)

같은 대상을 가리키는 여러 표기(예: `北`·`북한`, `Google`·`구글`, `KERI`·`전기연`·`한국전기연구원`)를 표준명 하나로 묶는 목록입니다.
별칭은 이 JSON 파일에서만 관리하며, 항목을 추가·수정한 뒤 **서버를 다시 시작하면** 반영됩니다 (코드 수정 불필요).

```json
{ "canonical": "SK하이닉스", "aliases": ["하이닉스", "SK hynix"], "type": "company", "categories": ["반도체"] }
```

| 필드 | 설명 |
|---|---|
| `canonical` | 표준명 (항목마다 고유) |
| `aliases` | 별칭 목록. `KT`처럼 영문으로 시작·끝나는 별칭은 앞뒤가 영문·숫자가 아닐 때만 일치 (`SKT` 안의 `KT`는 무시) |
| `type` | `company`, `government`, `organization`, `technology`, `country` 중 하나 |
| `categories` | 관련 분야: `AI`, `반도체`, `클라우드`, `사이버보안`, `통신`, `플랫폼` (없으면 `[]`) |

- 뜻이 여러 개인 약칭은 조건을 붙여 문맥이 맞을 때만 표준명으로 바꿉니다.
  ```json
  { "name": "MS", "context": ["클라우드", "애저", "윈도"] }      // 같은 제목에 이 단어 중 하나가 있을 때만 마이크로소프트
  { "name": "北", "notFollowedBy": ["美", "京", "欧", "極"] }   // '北美'(북미), '北京'(베이징)은 북한이 아님
  ```
- **중복 기사 제거에 사용**: 제목을 비교하기 전에 기업·정부·기관·국가(`company`, `government`, `organization`, `country`) 별칭을 통일합니다.
  `technology`(AI, HBM 등) 항목은 주제어라서 중복 비교에는 쓰지 않습니다.
- **분야 분류에 사용**: `analyzer.js`의 `CATEGORY_KEYWORDS`에는 분야별 키워드의 대표 표기만 적고, 같은 대상의 다른 표기는 이 DB에서 가져옵니다
  (예: 키워드 `D램` → `D램`·`DRAM`·`디램`을 하나의 근거로 셈). 분류 규칙(어느 단어가 어느 분야의 근거인지)은 `analyzer.js`, 표기 관리는 이 DB로 나뉩니다.
  분류 키워드인데 DB 항목의 `categories`에 그 분야가 없으면 서버 시작 시 `[별칭 DB]` 경고가 나옵니다.
- 표준명이 일반 명사와 겹치면 항목에 `notContext`를 붙입니다. 같은 글(제목+요약)에 그 단어가 있으면 이 항목으로 보지 않습니다.
  ```json
  { "canonical": "카카오", "notContext": ["코코아", "초콜릿", "카카오값", "카카오 선물"], ... }   // 코코아 원료 기사는 기업 카카오가 아님
  ```
- 여러 표기가 겹치면 긴 쪽을 우선합니다 (`네이버클라우드`가 `네이버`보다 우선).
- 잘못된 항목(필수 값 누락, 다른 항목과 겹치는 별칭 등)은 서버 터미널에 `[별칭 DB]` 경고를 남기고 건너뜁니다. 파일이 깨져도 서버는 별칭 없이 계속 동작합니다.
- 여러 뜻으로 쓰이는 표기는 넣지 않는 것이 안전합니다 (예: `IDC`는 데이터센터와 시장조사기관을 모두 가리킴).

## 중복 기사·분야 분류 규칙 요약

- **중복 기사** (`newsService.js`): 제목 유사도가 기준(0.5, 주어가 같으면 0.45) 이상이면 같은 사건으로 보되,
  상투 문구(`국감`, `우려 확산`, `대응책 마련` 등)와 부처명 말고 겹치는 사건 단서가 없으면 다른 사건으로 둡니다.
  제목 표현이 크게 달라도 ① 특정 이름(기업·기관, 영문 고유명사, 따옴표 속 이름) ② 사건 낱말 2개 이상(해킹·유출 등)
  ③ 같은 수량(예: 1만8359명 ≈ 1만8천여명) 또는 매우 비슷한 요약문이 모두 확인되면 같은 사건으로 묶습니다. 확인할 수 없으면 묶지 않습니다.
- **IT 분야 분류** (`analyzer.js`): 제목에 IT 키워드가 있어도 여러 소식 묶음(IT 업계 소식 모음은 제외)과 투자 상품·자금 흐름(ETF, 순매수 등) 기사는 제외합니다.
  시장·경제 기사는 IT가 주체·원인이거나 영향 표현(견인, 호황, 효과 등)이 붙을 때만 포함하고, IT가 다른 경제 요인과 `·`로 나열되면 제외합니다.
  판단이 어려우면 요약문에 IT 근거가 2개 이상일 때만 포함합니다.

## API 키 보안

- OpenAI API는 **백엔드(`backend/bannerWriter.js`)에서만** 호출합니다. 브라우저는 우리 서버의 `/api/banner`만 요청하고,
  OpenAI에 직접 접속하지 않습니다.
- API 키는 `.env` → 서버 환경변수로만 존재하며, 프론트엔드 HTML/CSS/JS 파일과 API 응답 어디에도 들어가지 않습니다.
- 서버는 `frontend/` 폴더 안의 파일만 제공하므로 브라우저에서 `/.env`나 `backend/` 코드를 열 수 없습니다.
- OpenAI 호출 오류는 서버 터미널에 상태 코드만 기록하고, 오류 원문(키 일부가 포함될 수 있음)은 출력하지 않습니다.
- `.gitignore`가 `.env`, `.env.*`(예: `.env.local`)를 제외하고 `.env.example`만 업로드되도록 설정되어 있습니다. `.env.example`에는 변수 이름만 있고 실제 키는 없습니다.
  실수로 키를 GitHub에 올렸다면 즉시 OpenAI 대시보드에서 해당 키를 폐기(revoke)하고 새로 발급하세요.

## API

### `GET /api/briefing?date=YYYY-MM-DD`
`date`를 생략하면 오늘(한국 시간)입니다. `&refresh=1`을 붙이면 캐시를 무시합니다.

```json
{
  "date": "2026-10-24",
  "updatedAt": "2026-10-24T08:28:22.016Z",
  "sources": ["전자신문", "ZDNet Korea", "연합뉴스", "Google 뉴스 RSS"],
  "news": [
    {
      "type": "news", "label": "사이버보안",
      "title": "...", "link": "https://...", "source": "ZDNet Korea",
      "publishedAt": "...",
      "impact": "보안 사고 대응 비용과 규제 리스크가 커져 ..."
    }
  ],
  "policies": [ { "type": "policy", "label": "과기정통부", "...": "..." } ]
}
```

### `GET /api/banner?date=YYYY-MM-DD`
메인 배너 3줄입니다. `mode`는 `ai`(OpenAI 분석, `model` 필드에 사용 모델 표시) 또는 `auto`(자동 집계)입니다.

```json
{
  "mode": "ai",
  "model": "gpt-4o-mini",
  "lines": ["핵심 이슈 문장", "산업 동향 문장", "정책·시사점 문장"],
  "date": "2026-10-24",
  "articleCount": 65,
  "generatedAt": "..."
}
```

## 동작 방식과 한계

- **메인 배너 (AI 분석)**: 기준일에 발행된 기사(분야별 최대 12건, 총 70건 이내)의 제목·출처·시각·요약문을
  OpenAI Responses API(`gpt-4o-mini`, `.env`의 `OPENAI_MODEL`로 변경 가능)에 보내고, 'IT 산업 전문 뉴스 에디터' 역할의 작성 지침(`bannerWriter.js`의 `SYSTEM_PROMPT`)에 따라
  3줄을 작성하게 합니다. 응답은 JSON 형식(line1~3)으로 받아 검증합니다.
  기사 본문 전체가 아닌 RSS 요약문만 보고 쓰므로, 세부 사실은 원문으로 확인하세요.
- **메인 배너 (자동 집계)**: API Key가 없거나 호출이 실패하면 분야별 기사 수와 대표 헤드라인으로 사실만 나열합니다.
  흐름을 해석하지 않으며 화면에 'AI 분석 아님'이라고 표시합니다.
- **기준일**: 언론사 RSS는 최근 1~2일치만 제공하므로, 지난 날짜는 주로 Google 뉴스 검색(날짜 범위 지정) 결과로 채워집니다.
  날짜 판정은 한국 시간 기준이며, 그날 기사가 5건보다 적으면 전날 기사로 카드를 보충합니다.
  정책 카드는 기준일 포함 최근 3일에서 고릅니다.
- Google 뉴스 검색 결과에 섞이는 무관한 기사(스포츠·도박 등)는 제목 키워드 검사로 걸러내지만, 완벽하지는 않습니다.
- **업계 영향**: `analyzer.js`의 키워드 규칙(예: '해킹' → 보안 투자 수요 증가)으로 생성합니다.
  AI가 기사 전체를 읽고 분석한 것은 아니므로 참고용입니다. 규칙은 `IMPACT_RULES`에서 바꿀 수 있습니다.
- 분류 키워드는 `analyzer.js`의 `CATEGORY_KEYWORDS`, 표시할 부처는 `MINISTRY_ENTRIES`(부처 표기는 별칭 DB), 출처는 `newsService.js` 상단에서 추가하거나 바꿀 수 있습니다.
  키워드의 다른 표기(영문명, 약칭 등)는 `data/aliases.json`에 추가합니다.
- 대한민국 정책브리핑(korea.kr) RSS는 현재 오류 페이지를 돌려주어 사용하지 않았습니다.
- Google 뉴스 RSS는 개인적·비상업적 용도로만 허용되므로 과제나 학습용으로만 사용하세요.
